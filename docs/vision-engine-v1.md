# Vision Engine v1

Первый модуль компьютерного зрения Jarvis Workshop для наблюдения за FlashForge AD5X через RTSP-камеру.

## Что умеет сейчас

- контролирует, что видеопоток открывается;
- оценивает движение в рабочей зоне по последовательности кадров;
- формирует осторожную оценку состояния `PRINTING`, `IDLE`, `UNKNOWN`;
- выявляет базовые проблемы самой камеры: слишком тёмный кадр, сильное размытие, замерший кадр;
- отправляет в Workshop API только смены состояния, heartbeat и подтверждённые тревоги;
- не управляет принтером и не останавливает задания автоматически.

## Почему v1 использует эвристики

До подключения реальных кадров конкретного принтера нельзя честно обучить надёжный детектор отрыва модели, spaghetti failure или завершения печати. Поэтому v1 даёт безопасный фундамент: поток кадров, временное окно, метрики качества, состояния и события. После записи реальных примеров поверх интерфейса `VisionEngine` можно добавить ML-модель.

## Калибровка

Основной параметр — `motion_threshold`. Он зависит от положения камеры, освещения и того, насколько сильно в кадре видны движения печатающей головы/стола.

Начальная конфигурация:

```yaml
vision:
  motion_threshold: 6.0
  printing_window: 8
  idle_window: 12
  frozen_frame_seconds: 20
```

После подключения камеры нужно собрать минимум несколько фрагментов: принтер простаивает, нормально печатает, печать завершена и искусственно плохой/закрытый кадр. По этим данным пороги можно откалибровать.

## Следующий детектор

`PrintFailureDetector` v2 должен работать по зоне `print_bed` и определять:

- смещение или отрыв детали от стола;
- spaghetti / хаотичную экструзию;
- отсутствие ожидаемого роста модели;
- потенциально пустую печать при движущемся принтере.

Любая такая тревога сначала должна проходить временное подтверждение на нескольких кадрах, чтобы не создавать ложные остановки и уведомления.
